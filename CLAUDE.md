# Instalar el taller de escritura

Este archivo guía a Claude Code cuando el usuario pide clonar e instalar el taller. Para trabajar en un libro ya instalado, usa `libro/CLAUDE.md` y sus procedimientos.

## Encargo de instalación

El usuario ya tiene Claude Code con su cuenta y Obsidian instalado. Tu trabajo termina cuando Obsidian está abierto en la bóveda correcta, el tablero funciona, Claudian está en español y en el modo de permisos elegido por el usuario, y una respuesta real de Claudian invita al usuario a traer sus archivos. Un script que termina sin errores no demuestra ese resultado.

1. Lee `README.md` y ejecuta `bash instalar.sh --consent` en macOS o `powershell.exe -NoProfile -ExecutionPolicy Bypass -File instalar.ps1 -Consent` en Windows 10/11 x64. La política indicada solo afecta ese proceso; no cambies políticas globales. Usa la ruta nativa de Windows, sin WSL. Ejecuta el comando desde este repositorio. La petición explícita de instalar autoriza esta preparación local. Usa el modelo de la sesión instaladora con `--model IDENTIFICADOR` en macOS o `-Model IDENTIFICADOR` en Windows cuando lo conozcas; en caso contrario se usa el modelo probado indicado por el instalador. El instalador informa su elección y crea un destino de respaldo local separado. No pidas al usuario comandos de Terminal, rutas internas, instalación de Python, copias de plugins ni configuración de tablero.
2. Mantén los archivos personales fuera del repositorio de distribución. El instalador prepara una copia privada independiente y preserva la estructura `libro`. No copies cuentas, tokens ni material de otras bóvedas a la distribución o al libro. La copia local de la configuración de Obsidian previa a este cambio sirve únicamente para restaurarla. No publiques ni hagas push.
3. Comprueba el resultado de `installation-result.json` en el destino que imprime el instalador. `prepared` significa que todavía falta la apertura; `starting` y `checking` son comprobaciones en curso. `sending` significa que se intentó enviar el mensaje; no demuestra aceptación ni respuesta. Solo `complete` con respuesta real, bóveda exacta, plugins cargados y modo de trabajo Seguro o YOLO satisface la instalación. No repitas un mensaje ya enviado ni borres el marcador para forzar otro intento.
4. Si aparece un error, resuelve la causa concreta dentro de este encargo y vuelve a comprobar. Una solicitud de permiso del sistema operativo o de Claude se explica en español; no se elude ni se finge aceptada. No conviertas un error técnico en una lista de tareas para el escritor. Si hace falta una intervención que solo él puede realizar, explica únicamente esa intervención y espera.
5. Deja Obsidian abierto con Claudian listo para recibir el material. La importación comienza cuando el usuario lo aporte. No inventes su libro ni uses material de prueba como si fuera suyo. Cierra con una frase breve que lo dirija a Claudian; no enumeres detalles técnicos ni conectores personales ajenos al taller.

Windows 10/11 x64 tiene una ruta nativa implementada, todavía sin verificación en un equipo Windows. Informa ese límite; solo una ejecución con respuesta real de Claudian puede demostrar el resultado local.

La preparación es local. No instala dependencias globales ni cambia la cuenta de Claude. Nunca cambies, fijes ni rebajes la instalación global de Claude Code: reutiliza la que el usuario ya utiliza, incluidas sus actualizaciones. Una diferencia de versión se registra como procedencia y no exige cambiar versiones ni pedir una verificación administrativa para guardar. Los errores funcionales concretos sí se diagnostican. Seguro y YOLO son elecciones del usuario; conserva su elección en una instalación existente. No afirmes compatibilidad que no se haya comprobado.
