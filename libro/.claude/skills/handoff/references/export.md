# Exportar el manuscrito solicitado

Esta rama requiere una petición explícita. Exportar no publica, envía, acepta prosa ni termina una etapa. Una etiqueta de manuscrito terminado necesita la decisión aparte del autor. Sigue el [contrato de trabajo](../../../references/workflow-contract.md).

1. Resuelve alcance, orden y metadatos. Lee `manuscrito/indice.md`, sección `Orden de lectura`, y usa solo esa lista o el subconjunto pedido, sin buscar todos los archivos por patrón. Confirma título, crédito, idioma y dedicatoria si hacen falta; valores opcionales desconocidos quedan vacíos. Los capítulos usan título humano y numeración opcional por posición actual, nunca por identidad estable. No dupliques un título ya presente.
2. Incluye `manuscrito/preliminares.md` solo si existe y se seleccionó para portada, dedicatoria o epígrafe. Índice de contenidos solo si se solicita. Planes, tablero, notas de investigación, bitácoras y alternativas no seleccionadas se excluyen.
3. Comprueba que `export` y su manifiesto están implementados en la versión instalada antes de ejecutar. No inventes argumentos. La base inicial de conservación no incluye exportación; en ese caso explica «La exportación no está disponible en esta instalación» y deja el alcance resuelto, sin fabricar archivos de salida ni usar un conversor por fuera del contrato.
4. La operación implementada debe crear una carpeta nueva `exportaciones/<fecha-hora>-<asunto>/`, copiar primero entradas estables y registrar orden, rutas y hashes de bytes y prosa. Recomprueba fuentes después de copiarlas. Si cambian durante captura, conserva intento inválido para inspección y no mezcles versiones. Nunca sobrescribas exportaciones previas.
5. Convierte solo esas copias a Markdown combinado y DOCX mediante Pandoc comprobado, con estilos básicos, sin transformaciones de tipografía inteligente ni ajuste de líneas que cambie la prosa. Usa metadatos de idioma español donde lo permita el formato. No añadas motor PDF o EPUB; un procesador de texto puede guardar después un PDF si el autor lo decide.
6. Retira únicamente cabecera y marcadores del sistema reconocidos. Preserva títulos, énfasis, encabezados de escena, `* * *`, rayas de diálogo, ¿/¡, tildes y ñ. Comentarios desconocidos, notas incrustadas o enlaces sin resolver producen lista de ubicaciones para decidir; no borres todo contenido entre corchetes o comentarios. No reemplaces encabezados del autor.
7. Verifica lista y cantidad de capítulos, omisiones, duplicados, título, cortes y prosa resultante. El manifiesto de salida registra orden, entradas y hashes, estados de versión, palabras por capítulo, conversor/opciones, hashes de salida y validez. Los recuentos son indicadores, no calidad. Distingue no revisado, aceptado y versión aceptada modificada después.
8. Si el exportador funciona pero falta el conversor DOCX, puede entregar Markdown con esa limitación explícita. No llames DOCX al archivo ausente. La existencia de un DOCX no prueba su aspecto: inspección en visor y páginas representativas quedan declaradas como pendientes si no se realizaron.
9. Guarda punto de bitácora con alcance, resultados y límites, enlaza salidas reales y deja etapa igual. Archivar el proyecto exige una petición distinta; exportar mantiene el libro editable.

La conversión se apoya en [la documentación de Pandoc](https://pandoc.org/MANUAL.html). La guía describe requisitos y recuperación; solo las pruebas de la instalación determinan qué salida puede prometerse.
